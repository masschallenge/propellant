Using Propellant

Propellant gives your product the MassChallenge look, ready to build with: our colors, type and spacing, plus the buttons, forms and app frame that screens are made of. Install it once and every page starts on brand, with keyboard support and contrast already handled, so your team spends its time on the product instead of rebuilding the same pieces.

What you get

Section titled “What you get”

Propellant comes in two layers. Tokens are our design decisions given names, such as --tint for the color of links and actions or --corner-lg for a rounded corner. Any website can use them. Components are ready made React pieces, such as Button and AppShell, built from those tokens.

Because every product draws from the same source, MassChallenge looks and works the same everywhere, and a change we make here reaches every team that installs the next version. You can start small, too: Propellant only styles the parts of a page you hand to it.

Pick your setup

Section titled “Pick your setup”

Find the row that matches what you are building. The rest of this guide follows it.

You are building Use
A site in WordPress, Squarespace, Webflow, Wix, HubSpot or plain HTML One stylesheet and a few class names, no install. Follow the websites guide.
A React application Components, tokens and the text style utilities.
A website styled with Tailwind CSS Tokens and utilities, plus components where the site uses React.
A website with its own CSS Tokens only, through CSS custom properties.

Propellant needs Node 22 or later and, for components, React 19.

Everything outside the boundary keeps its existing styles, so a product can move to Propellant one page at a time.

4. Frame the application

Section titled “4. Frame the application”

Signed in applications use AppShell: a Sidebar for places, a Toolbar for context and one main area for the page. On windows narrower than 1024px, the sidebar becomes an overlay that opens from a toolbar button.

SidebarItem and Button render plain links by default. Pass your router’s link component to linkAs to keep client side navigation, where pages change without a full reload.

5. Choose light or dark

Section titled “5. Choose light or dark”

AppShell takes an appearance value:

Value Effect
system Follows the light or dark setting of the operating system.
light Always light. Use it while a product still has pages designed only for light.
dark Always dark.

Outside AppShell, set data-theme="light" or data-theme="dark" on the boundary or any element inside it.

Tokens

Section titled “Tokens”

Use tokens by their role, never the raw values behind them:

Kind Examples
Color --label, --label-secondary, --bg, --bg-grouped, --tint, --critical, --separator
Type --type-family, --type-family-brand, and the text-body, text-headline utilities
Shape --corner-sm, --corner-md, --corner-lg, --corner-xl, --corner-capsule
Depth --shadow-float, --shadow-sheet, --material-bar
Motion --spring-snappy, --spring-smooth, --ease-standard
Layout --control-md, --row, --page-margin, --width-form, --space-4

The token reference on the documentation site lists every token with its light, dark, touch and reduced motion values.

What stays with you

Section titled “What stays with you”

Our components handle focus, keyboard support, contrast and announcements for screen readers. A few things only your product can do:

  • give every page one h1 and a sensible heading order,
  • write labels and button text that say what happens,
  • give icon only buttons an accessible name,
  • keep personal data out of analytics; fields mark their values private by default.

Versioning

Section titled “Versioning”

Propellant follows semantic versioning: the first number of a version changes only when an update can break your code. Install a tagged version and read the changelog before moving to a new major version.
